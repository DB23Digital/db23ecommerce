Critical Issues (Fix Immediately)

🚨
React SPA — No Server-Side Rendering. The entire site serves an empty <div id="root"></div> shell to search engines. All 8 pages are 12KB of identical HTML. Crawlers that do not execute JavaScript (Bing, AI bots, social scrapers) see zero content.
🚨
All 7 service pages have wrong canonical tags. Every URL (/ai-workshops/, /voice-ai/, /seo-services/, etc.) has <link rel="canonical" href="https://db23.co.za/"> — hardcoded in the HTML shell. Google is told to ignore all service pages as duplicates of the homepage. None of them can rank.
🚨
All 8 pages share identical title and meta description. Google cannot differentiate pages in SERPs. Service-specific keywords have no page to land on.
⚠️
Zero security headers. Content-Security-Policy, X-Frame-Options, HSTS, X-Content-Type-Options, and Referrer-Policy are all absent — security vulnerabilities and a trust signal gap.
⚠️
No backlink profile detected. Common Crawl shows zero referring domains. No external authority signals exist for any ranking category.

Quick Wins (1–2 Hours Dev Work)

✅
Fix canonical + titles + meta per route using react-helmet-async. Single highest-impact change on the site — unlocks all 7 service pages for independent ranking.
✅
Add security headers via .htaccess (30 minutes, zero risk).
✅

C2
Add unique titles & meta descriptions per route
Each of the 7 service pages needs a distinct, keyword-targeted title (≤60 chars) and meta description (≤155 chars). Done in the same Helmet change as C1. See Section 3.1 for recommended copy.
2 hrs devImpact: HIGHFix within 48h
C3
Fix og:url per page
OG URL is hardcoded to the homepage on all pages. When service pages are shared on LinkedIn or WhatsApp they show the wrong URL. Set dynamically alongside C1/C2.
Included in C1Impact: MEDIUMFix within 48h
H1
Add security headers via .htaccess
Add X-Content-Type-Options, X-Frame-Options, HSTS, Referrer-Policy, and Cache-Control headers to Apache config. Zero risk, 30 minutes. Also adds Cache-Control for the hashed JS bundle (immutable, 1 year).
30 minImpact: MEDIUMWeek 1

Enable Gzip/Brotli compression
The 612KB JS bundle is likely served uncompressed. Enabling compression on Apache reduces transfer to ~160KB — a 4× improvement in download time for first-time visitors.

Evaluate SSR / prerendering strategy
The canonical/title fix (C1/C2) buys time, but the long-term solution is Server-Side Rendering or Static Site Generation. Options: migrate to Next.js (best), use vite-plugin-ssr, or add a prerendering tool. Resolves the JS-rendering issue for all crawlers and dramatically improves Core Web Vitals.
1–2 days (Next.js)Impact: VERY HIGHWeek 2–3
